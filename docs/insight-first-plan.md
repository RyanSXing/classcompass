# Learning insights and teaching decisions

## Intended experience

The overview should answer three questions: how learning is developing, what to teach next, and who needs a follow-up. Keep the original purple/aqua design. Use plain language and put detailed counts behind an accessible evidence disclosure.

## Implementation plan

1. Derive dated, skill-specific learning observations from effective student responses, explanations, recorded help and reviewed findings. Describe consistency, changes in help, application in context and remaining uncertainty. Do not calculate an overall progress or mastery score. Earlier assignment views must not use later work to describe learning at that time.
2. Make the next lesson the main decision on the overview. Connect the recommendation to its reason, student evidence, teaching steps and success check. Preserve review before formal lesson changes and the existing timing/calendar constraints.
3. Show concise learning trends and individual follow-ups. Each interpretation must expose the dated work and help that support it. Keep reading flags separate from incorrect or missing answers.
4. Use the same learning context for live AI briefings and classroom chat. Clearly distinguish generated interpretations, data-based starting points and saved teacher decisions. Refresh stale briefings without erasing history.
5. Keep class totals, the student/assignment matrix, question patterns and comparison controls in “Explore the evidence.” Direct links to these views should open the disclosure automatically.
6. Verify first-use, historical scope, unsupported/uncertain work, evidence correction, briefing refresh, lesson generation/approval, saved lessons, mobile layout and keyboard use. Use isolated fictional data for mutations.

## Acceptance checks

- The default overview leads with a teaching decision, not correctness totals.
- Missing or supported work cannot become evidence of independent mastery.
- A changed reading or help record updates the learning picture and invalidates old AI interpretation.
- “Show me why” reaches exact dated responses and allows correction of current evidence.
- A teacher can reach the appropriate lesson from an insight, review sources, generate a proposal, edit or select changes, and retain the original plan.
- Saved changes and older lessons are labelled accurately; no generation or approval happens merely by opening a page.
- Raw results remain accessible and preserve distinct correct, incorrect, flagged and missing counts.

## Implemented

The overview now leads with the next lesson decision, three dated learning trends and three priority student follow-ups. Detailed analytics are collapsed by default and remain directly linkable. The learning selector separates correct reasoning, recorded help, unfinished work and unclear readings; its date boundary prevents later work from leaking into an earlier assignment view.

The assistant uses the same learning context. Earlier briefings are kept as history when evidence or the prompt changes. Lesson navigation now recognizes an applied proposal and opens the saved lesson instead of resurfacing an older draft. The original purple/aqua palette and teacher approval controls are retained.

Verification covers exact evidence links, corrected readings/help, historical scope, the sample classroom, raw analytics, student follow-ups, multiple drafts and a saved 45-minute lesson. See [verification results](verification-results.md) for final check counts and live-provider limitations.
